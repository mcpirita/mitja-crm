## Контекст

Дмитрий заносит реальных лидов пачками. Всплыли три боли:

1. **Быстрый ввод.** После создания лида приходится возвращаться в меню и
   открывать «Новый лид» заново — медленно при вводе нескольких лидов подряд.
2. **Несколько контактов на компанию.** У одной компании бывает несколько
   контактных лиц и несколько почтовых адресов, с которыми идёт переписка.
   Сейчас у лида одно поле `email` и одно `name`.
3. **Дубли.** Легко завести один и тот же лид дважды. Нужно ловить точные дубли
   (email / компания) и подсвечивать похожие.

## Решения (Q&A 2026-06-02)

- **Дубли при создании:** предупреждать, но давать сохранить («Создать всё
  равно»). Не жёсткая блокировка.
- **Контакты:** отдельная таблица `lead_contacts` (имя + email + роль + заметка).
  Главный контакт остаётся в полях `leads.name` / `leads.email`
  (денормализация — чтобы не переписывать письма/«сегодня»/списки). Доп.
  контакты — в `lead_contacts`.
- **Мердж:** в этой итерации **только обнаружение** похожих лидов (страница
  кандидатов). Объединение записей — отдельной итерацией позже.

## Фаза 3 — Предупреждение о дублях при создании

- [x] `src/lib/db/dedup.ts`: `findDuplicateLeads({email, company, name})` —
  точное совпадение email (в `leads.email` и `lead_contacts.email`),
  совпадение компании (без регистра), совпадение имени контакта.
- [x] API: `GET /api/leads/check-duplicates?email=&company=&name=`.
- [x] `LeadCreateForm`: при сабмите, если есть совпадения и пользователь ещё не
  подтвердил — показать предупреждение со ссылками на похожих и кнопку
  «Создать всё равно» (второй клик создаёт).

## Фаза 4 — Обнаружение похожих лидов (без мерджа)

- [x] Нормализация компании (нижний регистр, убрать GmbH/UG/e.V./пунктуацию)
  + похожесть (токены / расстояние) в `dedup.ts`.
- [x] `GET /api/leads/duplicates` — список пар-кандидатов по всей базе.
- [x] Страница `/leads/duplicates` — список похожих пар со ссылками
  (detection-only; кнопка «Объединить» — будущая итерация).
- [x] Ссылка на страницу из списка лидов / навигации.

## Будущее (вне этой итерации)

- Полный мердж: объединение двух лидов (контакты + история + заметки + spaces).
- Назначение любого контакта главным (промоут в `leads.name/email`).
