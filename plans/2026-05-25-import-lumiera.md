## Контекст

Дмитрий ведёт outreach по аренде площадей в собственном здании в Pforzheim. Площадей в здании несколько — гастро на первом этаже, кинозалы под перепрофилирование, пустые кабинеты, наружная площадка. Под каждого клиента подбирается своё помещение. Lumiera — название проекта, «клиенты под кинозалы» — рабочий заголовок таблицы, не единственный сегмент.

Текущий CRM содержит 4 теоретических сегмента (`gastro/services/office/entertainment`), которые не отражают реальный пайплайн. Реальные арендаторы в таблице — спорт-развлечения-комьюнити (Скалодром, Падель, Пилатес, Comedy Club, церкви и т.п.).

---

## Задача

1. **Заменить** enum сегментов в БД на реальный список из 22 типов.
2. **Импортировать** 81 строку из CSV с парсингом статусов и созданием backdated `outreach_events`.
3. **Сохранить** оригинальный текст статуса в `last_status_raw` (для аудита).
4. Не ломать существующий UI/API — он подхватит новые сегменты через `SEGMENT_LABELS_RU`.

### 2.2. Парсер статусов (`src/lib/import/parseStatus.ts`)
- [ ] Вход: текст статуса + текущая дата.
- [ ] Извлекает даты в форматах `DD.MM`, `DD.MM.YY`, `DD.MM.YYYY` (двузначный год → 20XX, без года → текущий год относительно тек. даты).
- [ ] Распознаёт события (по порядку обнаружения):
  - "Отправил первое письмо <дата>" / "Отпавил первое" → `email_sent` at дата.
  - "follow up <дата>" / "fup <дата>": 1-й по счёту = `fup1_sent`, 2-й = `fup2_sent`, дальнейшие — событие `other` (наша воронка только 2 фоллоуапа).
  - "презентация" → событие `other` с пометкой.
  - "Отказались" / "Не интересно" / "Невозможно разместить" / "Не подходит" → `reply_received` + лид → `replied_not_interested`.
  - "Есть интерес" / "интересно" → `reply_received` + лид → `replied_interested`.
  - "Только открываются" / "не идёт" / "Будут красть" → лид → `replied_later` или `dead` (без события).
  - "Ответ нет" / "пока нет" → лид → `awaiting_reply`.
- [ ] Выход: `{ status, events: [{ type, happened_at }], detected: string[] }` (последнее — для дебага).

### 2.3. Скрипт импорта (`scripts/import-lumiera.ts`)
- [ ] CLI: `tsx scripts/import-lumiera.ts <csv-path> [--commit]`.
- [ ] Без `--commit` → dry-run: печатает таблицу N | company | segment | status | events_count | first_event_date.
- [ ] С `--commit` → пишет в БД через `getDb()`, по одной строке, ошибки логирует и продолжает.
- [ ] Маппинг колонок CSV → leads:
  - `Название / описание` → `company`. `name` = `Контакт` если есть, иначе локальная часть email (`info` → "Контакт без имени").
  - `Тип бизеса` → `segment` (через карту нормализации, опечатки CSV → канонические значения).
  - `Сайт` → `website` (если начинается с http/www); иначе → `notes` префиксом "Источник: ".
  - `Почта` → `email`.
  - `Премичания` → если email — `notes` строкой "Доп. контакт: ..."; иначе — добавить к `notes`.
  - `Статус` → `status` + `last_status_raw` + `outreach_events`.
- [ ] `country` = "DE", `source` = "other".

## Критерий завершения

- В БД 81 лид с корректными сегментами.
- На `/today` видна реальная очередь follow-up по датам из таблицы.
- На карточке любого лида в timeline есть восстановленные события с правильными `happened_at`.
- `last_status_raw` хранит оригинальный текст для аудита.
- Старого enum `gastro/services/office/entertainment` в коде нет.
