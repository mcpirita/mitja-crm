## Задачи Фазы 2

### 2.1. Telegram-бот: утренний дайджест

- [ ] Завести бота через @BotFather. Сохранить `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID` (Дмитрия) в env.
- [ ] Эндпойнт `/api/cron/morning-digest` — формирует сводку:
  - просроченные действия (count + первые 3 строки),
  - due сегодня (count + первые 3),
  - новые лиды без касания (count).
- [ ] Cron на Railway (`*/30 9 * * *` Berlin time) → дёргает эндпойнт → шлёт в Telegram.
- [ ] Кнопка «Открыть CRM» (deep link на prod-URL).
- [ ] **Только чтение** — никаких inline-кнопок действий (это в более поздних итерациях).

### 2.2. Snooze (пауза 1–3 месяца)

- [ ] Поле `snoozed_until` (date) на `leads`.
- [ ] Кнопка «Отложить до…» на карточке: выбор даты (быстрые опции: +1 мес / +2 мес / +3 мес / кастом).
- [ ] Статус `snoozed` — лид не показывается в `/today`, пока не наступит дата.
- [ ] Когда `snoozed_until <= today` → автоматически возвращается в `/today` с задачей «Re-engage».

### 2.3. Архив мёртвых

- [ ] Soft delete: `lost` / `dead` уходят из основной таблицы, видны в `/leads?status=archived`.
- [ ] Возврат из архива одной кнопкой.

### 2.4. AI hook generator (опционально)

- [ ] Кнопка «Сгенерировать hook» на форме лида (рядом с `hook_text`).
- [ ] Эндпойнт `/api/ai/hook` принимает `{ company_name, website_url, segment }` → Claude API → возвращает 2–3 строки персонализированного hook'а на немецком (или EN с переводом).
- [ ] Промпт — DE, использует контекст оффера (одно здание, локация, целевая ниша).
- [ ] Cache по `(website, segment)` чтобы не тратить токены повторно.

## Критерий завершения

- Утренний дайджест приходит в Telegram каждое утро.
- Snooze работает — можно отложить лида, он возвращается в нужный день.
- Мёртвые / потерянные лиды убраны из основного списка, но не удалены.
- (Опционально) AI hook генерирует драфт за <5 секунд.
